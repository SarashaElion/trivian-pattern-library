# AGENTS

Read this repository in this order:

1. `STATUS.md`
2. `patterns.json`
3. `README.md`
4. `trivian_patterns/`
5. `tests/`
6. `examples/`

## Design rule

Every pattern should be:

- small enough to understand independently;
- explicit about its observable inputs;
- explicit about derived outputs;
- explicit about what it does **not** establish;
- dependency-light;
- covered by executable tests;
- usable without requiring the full TRIA stack.

## Interpretation rule

Do not turn a proxy into an ontology. A count ratio is not reciprocity itself; field presence is not embodiment itself; option count is not emergence itself; a declared consent flag is not legally or psychologically complete consent.

## Contribution rule

Prefer one narrow reusable function or class per pattern over large frameworks. If a proposed contribution requires orchestration, persistent governance, longitudinal state, or system-wide architecture, it likely belongs elsewhere in the Trivian ecosystem.
